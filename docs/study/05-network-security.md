# 05. 네트워크·보안·폐쇄망 — 입구 하나, 기본 거부, 인터넷 없이 설치

## 한 줄 요약
은퇴한 ingress-nginx 대신 Traefik으로 HTTPS 단일 입구를 만들고(cert-manager 사내 CA), NetworkPolicy로 "기본 거부 + 필요한 통신만 허용"을 14개 연결 테스트로 증명했다. 이미지·모델·설치 파일 7.5GB 번들만으로 **인터넷이 차단된 클러스터를 15분 21초 만에 재구축**하고 인수 검증을 통과했다.

## 용어 풀이 (비전공자용)
> 비유 기준: 클러스터 = 병원. 이번에는 병원에 **정문·출입 통제·외부 반입 검사**를 만들었다.

### 네트워크 기초
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **OSI 7계층** | 네트워크 통신을 7단계로 나눈 표준 모델. 실무에서는 주로 L2(스위치, MAC), L3(라우터, IP), L4(TCP/UDP, 포트), L7(HTTP 등 애플리케이션)을 말한다 | 택배의 **포장 → 주소 → 송장 → 내용물** 단계 |
| **IP 주소 / 포트** | IP는 컴퓨터의 주소, 포트는 그 컴퓨터 안 프로그램의 방 번호(HTTPS 443, PostgreSQL 5432) | **건물 주소 / 호실 번호** |
| **TCP / UDP** | TCP는 연결을 맺고 순서·도착을 보장(웹, DB), UDP는 확인 없이 빠르게 보냄(DNS, 영상) | **등기우편 / 일반 엽서** |
| **L4 vs L7** | L4 장비는 IP와 포트만 보고 넘기고, L7 장비는 HTTP 내용(주소 경로, 헤더)까지 보고 판단한다 | 건물 경비가 **호실 번호만 보고** 보냄 vs **용건까지 듣고** 담당 부서로 안내 |
| **DNS** | 이름(postgres)을 IP 주소로 바꿔 주는 전화번호부. 쿠버네티스에서는 CoreDNS가 맡는다 | **114 안내** |
| **NAT** | 내부 사설 IP를 바깥 공인 IP로 바꿔서 나가게 하는 것 | 회사 **대표번호로 발신** |
| **사설 대역** | 내부망 전용 IP 범위(10.x, 172.16~31.x, 192.168.x). 인터넷에서 직접 오지 않는다 | **내선 번호** |
| **iptables** | 리눅스 커널의 패킷 필터. "이 조건의 패킷은 버려라(DROP)" 같은 규칙을 건다 | 출입구의 **검문 규칙표** |

### 쿠버네티스 네트워크
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **CNI (Calico)** | Pod마다 IP를 주고 Pod끼리 통신하게 해 주는 네트워크 플러그인. Calico는 NetworkPolicy도 실제로 강제한다 | 병원 **내선 전화망 공사 + 통화 제한 장치** |
| **Service / ClusterIP** | 여러 Pod 앞에 고정 IP와 이름을 붙여 주는 것. Pod가 바뀌어도 같은 주소로 접속한다 | 진료과 **대표 내선번호** |
| **kube-proxy** | 각 노드에서 Service IP로 온 요청을 실제 Pod IP로 바꿔 보내는 규칙(iptables 등)을 만든다 | 대표번호 → **담당자 자리로 돌려 주는 교환원** |
| **Ingress / Ingress 컨트롤러** | 외부 HTTP(S) 요청을 받아 주소 경로별로 안쪽 서비스에 보내는 L7 입구 규칙(Ingress)과, 그 규칙을 실행하는 프로그램(Traefik) | 병원 **정문 안내 데스크** |
| **ingress-nginx 은퇴** | 가장 널리 쓰이던 Ingress 컨트롤러가 2026년 3월에 저장소가 보관(archived)되어 더 이상 보안 패치가 없다 | 오래 쓰던 경비 업체가 **폐업** |
| **Gateway API** | Ingress의 후속 표준. 역할(인프라 담당 / 앱 담당) 분리, TCP·gRPC 등 더 많은 기능 | 새 **출입 관리 표준** |
| **hostPort** | Pod의 포트를 노드의 포트에 직접 연결. 이번에는 Traefik을 노드의 80/443에 붙였다 | 안내 데스크를 **정문 바로 앞에** 설치 |
| **NetworkPolicy** | Pod 사이의 통신 허용·차단 규칙(라벨 기준). 기본은 "모두 허용"이라 직접 막아야 한다 | 병동 **출입 통제표** |
| **기본 거부 (default deny)** | 일단 모든 통신을 막고, 필요한 것만 하나씩 허용하는 방식 | "**명단에 없으면 출입 불가**" |
| **ingress / egress** | Pod로 **들어오는** 통신 / Pod에서 **나가는** 통신 | 병동 **입실 / 퇴실** |

### 암호화와 인증서
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **TLS / HTTPS** | 통신 내용을 암호화하고, 접속한 서버가 진짜인지 인증서로 확인하는 방식. HTTPS = HTTP + TLS | **봉인된 등기우편 + 발신인 신분증** |
| **인증서 / CA** | 인증서는 "이 서버가 localhost가 맞다"는 증명서, CA는 그 증명서에 서명해 주는 발급 기관 | **신분증 / 신분증 발급 관청** |
| **사설 CA (사내 CA)** | 회사가 직접 운영하는 인증 기관. 사내 시스템용 인증서를 발급한다. 직원 PC에 루트 인증서를 미리 넣어 두면 브라우저가 신뢰한다 | **사원증 발급 부서** |
| **cert-manager** | 쿠버네티스에서 인증서를 자동으로 발급하고, 만료 전에 갱신해 주는 도구 | 사원증 **자동 재발급 시스템** |
| **SAN (dnsNames)** | 인증서가 유효한 이름 목록(localhost, ax.hanbit.local). 요즘은 CN 대신 이걸로 확인한다 | 신분증의 **사용 가능 이름 목록** |
| **ECDSA** | RSA보다 짧은 키로 같은 보안 강도를 내는 서명 방식 | 더 얇지만 **똑같이 튼튼한 자물쇠** |

### 폐쇄망
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **폐쇄망 / 망분리** | 인터넷과 물리적·논리적으로 끊긴 내부망. 제조·금융·공공에서 많이 쓴다 | 외부 반입 검사가 있는 **보안 구역** |
| **반입 번들** | 설치에 필요한 모든 파일(이미지, 모델, 매니페스트, 차트, 데이터)을 미리 모은 꾸러미 | 보안 구역에 들고 들어가는 **공구 상자** |
| **SHA256 체크섬** | 파일 내용의 지문. 반입 전후 지문이 같으면 변조·손상이 없다는 증거 | 공구 상자의 **봉인 스티커** |
| **내부 레지스트리** | 회사 안에 두는 컨테이너 이미지 창고(Harbor, Nexus). 폐쇄망의 정석 | 보안 구역 안의 **자재 창고** |
| **digest 고정** | 이미지를 태그 대신 내용 지문(sha256)으로 지정. 같은 태그로 바꿔치기해도 영향이 없다 | 상품명 대신 **일련번호로 주문** |
| **멀티 아키텍처 이미지** | 하나의 이름 아래 amd64(인텔·AMD), arm64용 이미지를 묶은 것. 목차(index)가 플랫폼별 이미지를 가리킨다 | 같은 상품의 **국가별 전압 모델** 묶음 |
| **vendor (고정 설치 파일)** | 외부에서 받는 설치 파일을 저장소 안에 복사해 두고 거기서 설치하는 것 | 매번 사러 가지 않고 **비축해 둔 자재** |

### GPU 클러스터 네트워크
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **망 분리 4종** | 관리망(BMC·SSH), 서비스망(사용자 요청), 스토리지망(데이터), GPU 연산망(GPU끼리 데이터 교환)을 따로 둔다 | 병원의 **직원 통로 / 환자 통로 / 물자 통로 / 수술실 전용 복도** |
| **InfiniBand** | GPU 서버끼리 초저지연·고대역으로 데이터를 주고받는 전용 네트워크(NVIDIA Quantum, 400~800Gb/s) | **수술실 전용 고속 엘리베이터** |
| **RoCEv2** | RDMA over Converged Ethernet. 일반 이더넷 장비로 InfiniBand처럼 메모리를 직접 주고받는 방식. 손실 없는 설정(PFC, ECN)이 필요하다 | 일반 엘리베이터에 **우선 운행 모드**를 건 것 |
| **RDMA** | CPU를 거치지 않고 다른 서버의 메모리에 직접 읽고 쓰는 기술 | 택배를 **경비실 안 거치고 직접** 전달 |
| **Spine-Leaf** | 서버가 붙는 Leaf 스위치를 모든 Spine 스위치에 연결하는 2단 구조. 어느 서버끼리든 경로 길이가 같고, Spine을 늘려 확장한다 | 모든 층(Leaf)이 **모든 중앙 계단(Spine)과 연결**된 건물 |

## 핵심 개념
- **외부에서 들어오는 길은 하나로 만든다.** 서비스마다 포트를 열면 관리할 구멍이 늘어난다. L7 입구(Ingress) 하나에서 TLS를 끝내고(TLS 종료), 경로별로 안쪽 서비스에 보내고, 운영용 경로(`/metrics`)는 바깥에 내놓지 않는다.
- **쿠버네티스의 기본값은 "Pod끼리 전부 통신 가능"이다.** 그래서 한 Pod가 뚫리면 DB까지 그대로 닿는다. NetworkPolicy로 기본 거부를 걸고 통신 지도(누가 누구에게)를 그대로 규칙으로 옮긴다. 단, NetworkPolicy는 **CNI가 지원해야만** 실제로 막힌다(kind 기본 CNI는 무시함 → Calico를 쓴 이유).
- **폐쇄망 설치의 핵심은 "현장에서 아무것도 받지 않는다"**이다. 사무실에서 번들을 만들고, 같은 번들로 오프라인 리허설을 먼저 해 본다. 현장에서 파일 하나가 빠진 걸 발견하면 반입 절차를 처음부터 다시 해야 하기 때문이다.
- 비유: 병원에 **정문 하나**(Ingress)만 두고, 정문에서 **신분 확인과 봉인**(TLS)을 한다. 병동 사이 문은 **기본적으로 잠그고** 필요한 문만 열어 둔다(NetworkPolicy). 외부 물품은 **사전에 검사·봉인한 상자**(번들 + SHA256)로만 반입한다.

## 이 프로젝트에서 내가 한 것
- **ingress-nginx 은퇴 확인 → Traefik으로 대체**: GitHub API로 확인하니 `kubernetes/ingress-nginx`가 `archived=True`(마지막 릴리스 v1.15.1, 2026-03)였다. Traefik(Ingress)과 Envoy Gateway(Gateway API)를 비교해서, 일정과 현장 호환성을 기준으로 Traefik v3.7.13을 골랐다. control-plane 노드에 hostPort 80/443으로 붙이고 HTTP는 HTTPS로 301 리다이렉트한다.
- **TLS**: cert-manager v1.21.2로 "자체 서명 부트스트랩 → 한빛정밀 사설 루트 CA(10년, ECDSA) → hanbit-ca 발급자 → 서버 인증서(90일, 만료 15일 전 자동 갱신)" 체계를 만들었다. `openssl s_client`로 `Verify return code: 0`을 확인했고, CA 없이 접속하면 curl이 거부(exit 60)하는 것도 확인했다.
- **단일 입구**: `https://localhost/` → web-ui, `/api` → 게이트웨이. 게이트웨이의 `/metrics`, `/readyz`는 바깥에서 404다.
- **NetworkPolicy 11개**: 기본 거부 + DNS만 허용 + 앱별 최소 허용(web-ui → 게이트웨이, 게이트웨이 → LLM·임베딩·DB, 수집 → MinIO·임베딩·DB 등). 게이트웨이는 MinIO를 쓰지 않아서 허용하지 않았다.
- **연결 테스트 `scripts/netpol-test.sh`**: 실제 Pod 안에서 TCP 연결을 시도한다. **적용 전에는 14개 중 9개 실패**(전부 열려 있음), **적용 후 14/14 통과**. 라벨 없는 "외부인" Pod는 DB·게이트웨이·MinIO·인터넷 모두 막히고 DNS만 된다.
- **적용 후 기능 회귀 확인**: Pod 헬스체크, 수집 Job, 마이그레이션 Job, 권한 테스트 14개가 모두 정상이었다(어제 RLS 회귀 경험 때문에 바로 확인).
- **폐쇄망 리허설**
  - 번들 7.5GB: 이미지 16종 4.3GB, 노드 이미지 0.4GB, 모델 2.9GB, 설치 소스, SHA256 20개. 이미지 목록은 차트·vendor 매니페스트를 렌더링해서 선언적으로 뽑았다.
  - 클러스터를 지우고 새로 만든 직후 **모든 노드에서 iptables로 사설 대역 외 전부 DROP**했다. 노드에서 docker hub 접속이 실패하는 것을 확인했다.
  - 번들만으로 이미지 적재 → CNI → 인증서 → 입구 → 차트 → **모델 tar를 PVC에 복원** → 데이터 수집까지 **921초(15분 21초)**. 인수 검증(외부 차단 유지, HTTPS, NetworkPolicy 14/14, 권한 14/14) 통과.
  - 절차서 `docs/airgap-install.md`: 사전 협의 체크리스트, 단계별 소요 시간, 문제 5건과 대응, 운영 전환 후속 과제.
- **리허설에서 겪은 문제 5가지** (각각 진단 → 원인 → 조치):
  1. 번들 생성 중 `error getting credentials` 반복 → WSL Docker CLI가 pull마다 Windows 자격 증명 도우미를 호출하다 vsock 시간 초과. 공개 이미지라 빈 `DOCKER_CONFIG`로 익명 pull.
  2. 이미지 적재 `content digest not found` → Docker Desktop의 containerd 저장소에서 `docker save`가 멀티 아키텍처 목차를 통째로 저장(내용물은 amd64만). `--platform linux/amd64`로 저장.
  3. digest 고정 MinIO 이미지를 노드에서 못 찾음 → 태그 없는 이미지는 이름이 안 남고 `docker save`가 digest를 바꿈. `pinned-<digest>` 태그로 반입하고 SHA256으로 무결성 보장. **현장에서는 내부 레지스트리 push가 정석**이라는 결론.
  4. 번들 스크립트가 지운 클러스터에 의존 → 설치 파일에서 목록을 뽑도록 변경.
  5. 깨끗한 DB에서 감사 로그 테스트 실패 → 테스트가 실행 순서와 과거 기록에 의존하고 있었다. 오늘 낮의 "간헐적 실패"의 진짜 원인으로 보이며, 테스트를 독립적으로 고쳤다.
- **비밀값 점검**: 저장소·ConfigMap·환경변수·Helm 값에 비밀값 평문 없음, 전부 secretKeyRef. 후속 과제로 etcd 암호화 미설정, 토큰 자동 마운트 10/10, MinIO 루트 계정 공유를 기록했다.

## 실제 기업 환경에서는
- **GPU 클러스터는 네트워크를 4개로 나눈다.**
  - 관리망: BMC(iDRAC/iLO), SSH, 1~10GbE
  - 서비스망: 사용자 요청, API, 25~100GbE
  - 스토리지망: NFS·S3·병렬 파일시스템, 100~400GbE
  - **GPU 연산망**: 학습 시 GPU끼리 그래디언트를 교환(All-Reduce), 400~800Gb/s, InfiniBand 또는 RoCEv2. 서버당 GPU 수만큼 NIC를 두는 "rail-optimized" 구성
- **InfiniBand vs RoCEv2**: InfiniBand는 전용 스위치·케이블에 손실 없는 전송과 낮은 지연이 기본이라 대규모 학습에 강하다(NVIDIA 생태계). RoCEv2는 이더넷 장비를 쓰고 기존 운영 인력·도구를 활용할 수 있지만, 손실 없는 이더넷(PFC, ECN) 튜닝이 까다롭다. 추론 중심이면 GPU 연산망 비중이 작아서 이더넷으로 충분한 경우가 많다.
- **Spine-Leaf**: Leaf(ToR) 스위치마다 모든 Spine에 올라가는 구조라, 서버 간 홉 수가 일정하고 Spine을 늘려 대역을 키운다. 오버서브스크립션 비율(아래로 내려가는 대역 : 위로 올라가는 대역)을 GPU 연산망은 1:1로 설계한다.
- **폐쇄망 현장**: 내부 레지스트리(Harbor)에 `skopeo`/`crane`으로 이미지를 digest 그대로 옮기고, containerd에 미러를 설정한다. OS 패키지는 RPM/APT 미러, GPU 드라이버는 패키지 또는 GPU Operator의 드라이버 컨테이너로 반입한다. 모델은 내부 오브젝트 스토리지나 모델 레지스트리에 버전과 함께 올린다. 반입 매체는 보안 USB나 망연계 솔루션이고, 반입 승인과 백신 검사 절차가 있다.
- **입구**: ingress-nginx를 쓰던 고객은 Gateway API(Envoy Gateway, NGINX Gateway Fabric) 또는 Traefik·HAProxy로 마이그레이션해야 한다. OpenShift는 자체 Router(HAProxy 기반)를 쓴다. 외부 L4 로드밸런서(F5, MetalLB)를 앞에 두는 경우가 많다.
- **인증서**는 고객사 사내 CA(AD CS)에서 받거나, cert-manager가 사내 CA(ACME/Vault)를 발급자로 쓰게 한다.

## 에티버스그룹 사업과의 연결
이테크시스템의 통합 구축 범위에 **스위치·보안**이 들어 있다. 제조 고객의 상당수가 폐쇄망이라, "인터넷 없이 설치하고 그 결과를 인수 검증으로 증명하는 절차"가 실제 구축 업무의 큰 부분이라고 생각한다. 그룹 파트너인 Cisco(네트워크)와 Red Hat(OpenShift)이 이 영역의 실제 제품이고, 이번 리허설 문서는 현장 체크리스트의 초안 역할을 한다.

## 자주 쓰는 명령어
```bash
# 리눅스 네트워크 점검
ip a                     # 인터페이스·IP
ip route                 # 라우팅 표 (기본 게이트웨이)
ss -tulnp                # 열려 있는 포트와 프로세스 ("address already in use" 범인 찾기)
ping -c 3 <host>         # L3 도달 (ICMP가 막힌 곳도 많으니 실패 = 장애는 아님)
traceroute <host>        # 경로상 어디서 끊기는지
curl -v https://<host>   # L7: DNS → TCP 연결 → TLS 핸드셰이크 → HTTP 응답 순서로 보여 줌
dig <name> / nslookup    # DNS 조회
nc -z -w 3 <host> <port> # 포트 열림 여부만 빠르게
openssl s_client -connect localhost:443 -servername localhost   # 인증서 체인·검증
iptables -L -n -v --line-numbers                                # 방화벽 규칙과 적중 수

# 쿠버네티스
kubectl get ingress,svc,endpointslices -A
kubectl get networkpolicy -n ai-platform
kubectl -n cert-manager get certificate,clusterissuer
kubectl describe certificate ax-tls -n ai-platform     # 발급 상태, 만료일
./scripts/netpol-test.sh                               # 허용·차단 표
./scripts/airgap-bundle.sh / airgap-install.sh / airgap-verify.sh
```

## 예상 면접 질문 5개 + 모범 답변

**Q1. 쿠버네티스에서 외부 요청이 Pod까지 가는 경로를 설명해 주세요.**
> 제 구성 기준으로 말씀드리면, 브라우저가 https://localhost로 오면 노드의 443 포트에 hostPort로 붙어 있는 Traefik이 받습니다. Traefik이 TLS를 풀고, Ingress 규칙에서 경로가 /api면 ax-gateway 서비스로, 나머지는 web-ui 서비스로 보냅니다. 서비스는 고정 IP이고, 실제 Pod IP로 바꿔 주는 건 kube-proxy가 만든 규칙입니다. Pod끼리의 통신은 Calico가 깔아 준 네트워크로 가고, 서비스 이름을 IP로 바꾸는 건 CoreDNS입니다. 운영 환경이라면 Traefik 앞에 L4 로드밸런서가 하나 더 있다고 보시면 됩니다.

**Q2. NetworkPolicy를 어떻게 설계하고 어떻게 검증했나요?**
> 먼저 통신 지도를 그렸습니다. 채팅 화면은 게이트웨이로만, 게이트웨이는 LLM, 임베딩, DB로만, 수집 작업은 MinIO, 임베딩, DB로만 가면 됩니다. 그다음 네임스페이스 전체에 기본 거부를 걸고, DNS와 이 지도에 있는 통신만 허용했습니다. 게이트웨이는 MinIO를 안 써서 일부러 막았습니다. 검증은 실제 Pod 안에서 TCP 연결을 시도하는 스크립트로 했는데, 적용 전에는 14개 중 9개가 기대와 달리 열려 있었고 적용 후 14개 모두 기대대로 나왔습니다. 막고 나서 정상 기능이 깨지지 않았는지도 수집 작업과 권한 테스트로 바로 확인했습니다.

**Q3. 폐쇄망 고객사에 AI 플랫폼을 설치한다면 어떻게 하시겠어요?**
> 현장에서는 아무것도 인터넷에서 받지 않는다는 원칙으로 준비합니다. 사무실에서 이미지, 모델, 설치 매니페스트, 차트를 번들로 만들고 SHA256 체크섬을 남깁니다. 그리고 반입 전에 같은 번들로 인터넷을 막은 환경에서 설치 리허설을 합니다. 실제로 해 보니 번들 7.5기가로 15분 정도에 재구축됐고, 그 과정에서 멀티 아키텍처 이미지 저장 문제나 digest가 바뀌는 문제처럼 해 보기 전에는 몰랐던 문제를 다섯 개 찾았습니다. 현장에 내부 레지스트리가 있으면 이미지를 digest 그대로 push하는 게 정석이고, 반입 절차나 사내 CA, DNS, NTP는 사전에 고객과 협의해야 할 항목으로 체크리스트에 정리해 뒀습니다.

**Q4. GPU 클러스터의 네트워크는 어떻게 구성하나요? InfiniBand와 RoCE의 차이는요?**
> 보통 관리망, 서비스망, 스토리지망, GPU 연산망을 분리합니다. 학습에서는 GPU끼리 대량의 데이터를 계속 교환해서, 연산망을 400기가 이상으로 따로 두고 CPU를 거치지 않는 RDMA를 씁니다. InfiniBand는 전용 장비라 손실 없이 지연이 낮은 게 기본이고, RoCEv2는 이더넷 장비로 RDMA를 하는 방식이라 기존 이더넷 운영 경험을 살릴 수 있지만 손실 없는 설정을 잘 맞춰야 합니다. 구조는 Spine-Leaf로 서버 간 경로를 일정하게 하고요. 다만 이건 제가 공부로 이해한 수준이고 실제 스위치를 구성해 본 적은 없어서, 입사하면 가장 먼저 배우고 싶은 부분입니다.

**Q5. TLS 인증서는 어떻게 관리했나요? 만료되면 어떻게 되나요?**
> cert-manager로 사설 루트 CA를 만들고, 그 CA로 서버 인증서를 발급하게 했습니다. 서버 인증서는 90일짜리이고 만료 15일 전에 자동으로 갱신되게 설정했습니다. 인증서가 만료되면 브라우저와 클라이언트가 접속을 거부해서 서비스 전체가 멈춘 것처럼 보입니다. 실제 장애 원인으로 꽤 흔하다고 알고 있어서, 자동 갱신과 함께 만료 임박 알람도 걸어야 한다고 생각합니다. 고객사라면 보통 사내 CA가 이미 있으니 cert-manager의 발급자만 그쪽으로 바꾸면 됩니다.

**보너스 Q. 오픈소스 컴포넌트가 지원 종료되면 어떻게 판단하나요?** (실제 겪은 문제)
> 이번에 ingress-nginx를 쓰려다가 저장소가 2026년 3월에 보관 처리된 걸 확인했습니다. 은퇴한 컴포넌트를 새로 구축하면 보안 패치를 못 받으니 대안을 비교했는데요, Traefik은 기존 Ingress 방식 그대로라 빨리 적용할 수 있었고, Envoy Gateway는 차세대 표준인 Gateway API를 쓰지만 설정이 더 복잡했습니다. 일정과 고객사 현장 호환성을 기준으로 Traefik을 골랐고, 장기적으로는 Gateway API로 옮기는 게 맞다고 노트에 정리했습니다. 고객사에서 ingress-nginx를 쓰고 있다면 지원 종료 사실과 마이그레이션 계획을 먼저 알리는 게 기술지원 엔지니어의 역할이라고 생각합니다.

## 꼬리 질문 3개 + 답변 방향
1. **"NetworkPolicy가 라벨 기준이면, 누가 같은 라벨로 Pod를 만들면요?"** → 맞다. 라벨은 위조 가능하다. 그래서 Pod 생성 권한을 RBAC로 제한하고, 네임스페이스 단위 분리, Admission 정책(Kyverno, OPA Gatekeeper)으로 라벨·이미지를 검증한다. 더 강하게는 서비스 메시(mTLS, 서비스 계정 기반 신원)를 쓴다.
2. **"kubectl port-forward는 NetworkPolicy에 막히나요?"** → port-forward는 API 서버 → kubelet → Pod 네트워크 네임스페이스로 직접 들어가서 일반 Pod 간 경로와 다르다. 그래서 정책으로 막는 대상이 아니고, **RBAC의 pods/portforward 권한**으로 통제한다.
3. **"폐쇄망에서 모델을 업데이트하려면?"** → 새 모델을 사무실에서 받아 해시와 함께 반입하고, 내부 모델 저장소에 버전별로 올린 뒤, 스테이징에서 품질 평가(같은 질문 세트) 후 values의 모델 버전을 바꿔 배포한다. 롤백할 수 있게 이전 버전도 보관한다.
