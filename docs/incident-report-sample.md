# 장애(보안 이벤트) 보고서 — 사내 AI 검색 권한 필터 비활성화

| 항목 | 내용 |
|---|---|
| 문서 번호 | INC-2026-1008-01 |
| 고객사 | 한빛정밀 (가상) |
| 시스템 | 사내 AI 어시스턴트 (권한 기반 RAG) |
| 등급 | 보안 이벤트 — **유출 없음 확인** (잠재 위험: 높음) |

| 상태 | 조치 완료, 후속 과제 진행 중 |

> 이 보고서는 포트폴리오 프로젝트의 장애 시나리오 7을 실제 고객사 보고 형식으로 작성한 예시입니다. 시각은 한국 시간(KST), 로그 원문은 UTC입니다.

## 1. 요약
오전 배포에 **앱 단의 문서 권한 필터를 끄는 설정**(`APP_FILTER_ENABLED=false`)이 포함되어, 이론상 생산 작업자 계정이 품질팀 전용 문서(불량 보고서, 고객 클레임)를 검색할 수 있는 상태가 약 30분간 지속되었습니다. 조사 결과, **두 번째 방어선인 데이터베이스 행 수준 보안(RLS)이 작업자 권한의 품질 문서 조회를 차단**하여 **실제 유출은 없었습니다.** 해당 시간대의 모든 질의는 감사 로그로 확인했습니다.

## 2. 타임라인 (KST)
| 시각 | 내용 |
|---|---|
| 17:40 | 배포: 게이트웨이 설정 변경 (`APP_FILTER_ENABLED=false`) |
| 17:42 | 정보보안팀 문의 접수: "작업자 계정의 품질 문서 접근 가능 여부와 유출 여부 확인 요청" |
| 17:43 | 1차 확인: 운영 설정에서 앱 권한 필터 비활성화 확인 (원인 특정) |
| 17:44 | 감사 로그 조회: 작업자 계정이 "성형 깊이 불량 원인과 고객 클레임"을 질의한 기록 확인 → 사용 문서 **0건**, 결과 "근거 없음" |
| 17:45 | DB 직접 검증: 앱 계정으로 작업자 권한 조회 시 품질 문서 **0건**(품질 권한은 25건) → RLS 정상 동작 확인 |
| 17:47 | 조치: 설정 원복(`APP_FILTER_ENABLED=true`) 및 재배포, 원복 검증 |
| 17:50 | 고객 1차 보고 |

## 3. 영향 범위
- **노출 가능 대상**: 생산팀 작업자 권한 계정
- **노출 가능 정보**: 품질 불량 보고서 5건(고객 클레임 1건 포함)
- **실제 노출**: **없음.** 해당 시간대 작업자 계정의 모든 질의에서 품질 문서가 답변 근거로 사용된 기록이 없음
- **서비스 영향**: 없음 (답변 기능 정상)

## 4. 근본 원인
- **직접 원인**: 디버깅용 설정값이 운영 배포 값에 섞여 들어갔습니다.
- **구조적 원인**: 배포 전 검증에 "보안 관련 설정값 검사"와 "역할별 권한 자동 테스트"가 필수 단계로 들어가 있지 않았습니다.
- **피해가 없었던 이유**: 권한 통제를 ① 앱 검색 필터 ② DB 행 수준 보안 두 겹으로 설계했고, ②는 앱 설정과 무관하게 요청 사용자의 역할에 허용된 행만 반환합니다.

## 6. 고객 공유 문구 (안)
> 오늘 오후 사내 AI 어시스턴트 배포 과정에서 문서 권한 검사 설정 하나가 비활성화된 채 적용되었습니다. 즉시 원인을 확인해 원래 설정으로 복구했습니다. 시스템은 권한을 이중으로 검사하도록 설계되어 있어, 해당 시간에도 데이터베이스 단계에서 권한 밖 문서 조회가 차단되었습니다. 감사 기록을 전수 확인한 결과 **품질팀 전용 문서가 다른 부서에 제공된 사례는 없었습니다.** 재발 방지를 위해 배포 전 권한 자동 검사를 필수 단계로 추가하겠습니다. 감사 로그 원본이 필요하시면 제공해 드리겠습니다.
