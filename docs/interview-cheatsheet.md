# 면접 당일 요약 (치트시트)

> 면접 직전 30분에 이 장만 다시 읽는다. ✏️ 표시는 본인이 직접 채워야 하는 부분이다.

## 1. 30초 프로젝트 소개 (그대로 말해도 되는 원고)
> "에티버스그룹이 만드는 AXhub처럼, 사내 AI가 문서를 읽되 **직원 권한 범위 안에서만 답하는 플랫폼**을 쿠버네티스 GPU 인프라에 직접 구축해 봤습니다. 가상 제조사 데이터로 sLLM, 문서 검색, AI 에이전트를 올리고, **앱 필터와 DB 행 수준 보안 두 겹**으로 권한을 막았습니다. 인터넷이 막힌 상태에서 15분 만에 전체를 다시 설치하는 폐쇄망 리허설, 모니터링과 알람, 백업 복구 훈련, 장애 8종 진단, 고객 사이징 제안서까지 했고, 모든 결과는 직접 측정한 수치로 남겼습니다."

## 2. 1분 자기소개 뼈대
1. **전공·기술 기반**: 컴퓨터공학, 웹 백엔드(Spring Boot·FastAPI·NestJS), DB(PostgreSQL·MSSQL), AWS 경험
2. **현장 경험**: 제조기업 IT팀 9개월 — ERP(C#·MSSQL) 개발·운영, 국내외 법인 계정·권한 운영, **권한 요청 절차를 "요청-검토-반영-이력 관리"로 표준화해 누락률 0%대**, 권한 기반 사내 문서관리 시스템 개발 ✏️ (구체적 상황 한 문장)
3. **왜 AI 인프라인가**: ✏️ (예: 현장에서 시스템을 안정적으로 운영하는 일이 맞았고, 생성형 AI가 사내 문서를 다루게 되면서 인프라와 권한 설계의 중요성을 느꼈다)
4. **준비한 것**: 이 프로젝트 (30초 소개 압축)
5. **마무리**: ✏️ (입사 후 가장 먼저 배우고 싶은 것: 실제 GPU 서버 구축, GPU Operator, 폐쇄망 고객 현장)

> 경력 관련 질문(짧은 경력, 이전 지원 이력)은 사실대로, 배운 점과 이번 지원과의 연결로 답한다. ✏️

## 4. 꼭 말할 사례 5개 (상황 → 행동 → 결과 → 배운 점)
1. **권한 필터 사고 조사** — 보안팀이 작업자의 품질 문서 접근 여부를 물음 → 설정(필터 false) 확인 → 감사 로그(사용 문서 0건) → 앱 계정으로 DB 직접 조회(작업자 0 / 품질 25) → **"유출 없음"을 증거로 보고서 작성**. 배운 점: 권한은 두 겹, 사고 보고는 추측이 아니라 증거로.
2. **폐쇄망 리허설** — 인터넷 차단 상태 재설치 → 멀티 아키텍처 저장 실패, digest 변경, 자격 증명 시간 초과 등 함정 5개 발견·해결 → 15분 21초 재구축. 배운 점: 반입 전 오프라인 리허설, 현장은 내부 레지스트리가 정석.
3. **모델 적재 교착** — 적재 Job이 10분째 대기 → 모델 폴더 크기, 서버 로그, EndpointSlice 순으로 확인 → "Service는 Ready Pod에만 연결, Ready 조건은 모델 있음" 교착 → 관리용 Service 분리. 배운 점: readiness와 트래픽 경로의 관계.
4. **보안 강화가 배치를 깨뜨림** — RLS 적용 후 수집 CronJob 3회 실패 → 로그(COPY 미지원) → 트랜잭션 덕에 데이터 무사 → 임시 테이블 경유로 수정, Job 실패 알람 추가. 배운 점: 변경 후 쓰기 경로까지 회귀 테스트.
5. **OOM 진단 실수와 교정** — 처음엔 63분 전 다른 Job 오류를 원인으로 짚음 → 시점·경로가 안 맞음을 깨닫고 Last State(OOMKilled/137) → Helm 이력으로 메모리 축소 배포 확인. 배운 점: "언제부터, 어느 경로"를 항상 함께 본다.
